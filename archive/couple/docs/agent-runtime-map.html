Relational Agent Runtime Map

What wakes the pipeline up, what the pipeline does, and exactly where the LLM gets called — with which prompt and which context. We trace the context all the way back to its source. Based on the codebase at: app/src/lib/agent/*, 2026-07-26. Section layout, vocabulary, and event rules are now determined by the relationship profile (lib/agent/profiles) — the values below are for the default Romantic profile. In the Business profile there are 6 sections (Meeting log·Agreements·Action items·Contacts· Open questions), there is no photo rule, and events are 📅 meeting / 🤝 intro.

03 The 6 LLM call points

There are exactly six places where the agent calls the model. Each has a hardcoded prompt, and no tools are attached — the model returns JSON text, and it's code all the way down that interprets it and writes files.

① Draft a document edit pipeline.ts:143 · llmEdits()
Role
Reads a new batch of messages and drafts an edit to append to the relationship document
System prompt
Assigns the "record-keeper" role + output schema [{section, markdown, sourceMessageIds, event?}] + Timeline event classification rules (date/first-met) + "today's date is X, write the date the event happened, not the date it was mentioned" + "do not repeat facts already in the document" + photo embed format + "if you put - in front of it, the photo won't render" + "'midnight natas' is not a person's name — when in doubt, trust the photo over the spelling"
Context
  • Current state of the document — the profile's full sections, as JSON, all at once (no cap)
  • New message batch — in the format [id] (author, 8 chars) body [attached: …]
  • Actual photos — uploaded images inlined as data URLs (vision input)
Source
Document → OKF file via readOkfSectionTexts() · Messages → Postgres chat_messages (unprocessed + after consentAt) + call_utterances (finished calls only) · Photos → disk, public/uploads/*
Parameters
maxTokens 1500 · temperature 0.2
Output post-processing
  • Normalize section keys — even if the model writes Overview, it becomes overview (parse-edits.ts:32)
  • Block source forgery — any id that isn't actually in this batch is discarded (pipeline.ts:378)
  • Strips stray [uuid]s mixed into the prose, model-invented Sources: lines, and leading dates
  • Hard rule if the quoted message has a photo, it is promoted to the event declared by the profile regardless of the model's judgment (Romantic = date, Business = no rule)
  • Files only ever get appended to — there is no path to edit or delete existing lines
On failure
Call failure or parse failure → falls back to fakeEdits(), a deterministic record (dumps the message into the Timeline as-is). A record is always left behind
② Whether to reply / what to say respond.ts:152 · llmDecision()
Role
For a single new message, decide {"action":"reply"|"silent"} and draft the reply text
System prompt
Persona (agentConfig.persona.name) + room name + the user-specified systemPrompt appended + "if mentioned, always reply; otherwise, per the proactive setting, reply briefly only when something must be known, else stay silent" + "answer from the document; partial memory still counts as an answer" + "when recommending something, name the memory behind it and attach that photo" + "a preference not in the document does not exist" + "don't defer something you already know as an open topic" + output JSON schema
Context
  • Full text of every section of the document — including sections left behind by an earlier profile (no per-section cap)
  • Last 20 messages of the conversation — (author, 8 chars) body, reverse-chronological order flipped back to forward order
  • The new message + a mentioned boolean
  • Document root link /p/{rootPageId}
Source
Document → OKF file · Conversation → last 20 from chat_messages · Persona → users.agentConfig · Link → agent_room_states
Parameters
maxTokens 600 · temperature 0.4
Predetermined by code
  • Mention detection string contains @agent or @{display name} (respond.ts:98)
  • A secret message is unconditionally treated as a mention — being addressed to them is already the target, no need for another @
  • The visibility scope of the reply is also decided by code: an answer to a secret question goes only to that member
Output post-processing
Attachments must start with /uploads/ and contain no .., max 4 photos. If the model omits an attachment or makes up a URL, the code picks a photo directly from the document using a word-overlap score ≥ 2 (respond.ts:83). JSON parse failure → if mentioned, send the raw text as-is; otherwise stay silent
③ Does the draft contradict the record (decline) guard.ts:132 · checkDraft()
Role
Checks a draft against the relationship record before the human sends it. The human keeps final say — allowing a forced send is part of the contract
System prompt
Assigns "fact-checker" role + blocks only under an AND condition: contradicts (directly contradicts a recorded fact) and harmful (sending it as-is would hurt the other person or damage the relationship) + "never block just because it isn't in the record" + "if it contradicts, copy the sentence verbatim from the document into evidence (no summarizing or paraphrasing)"
Context
Only non-empty sections, as ### heading + body, with a 6,000-character cap + the draft text
Source
OKF file (if agent_room_states has no path, treated as no document and passed immediately)
Parameters
maxTokens 500 · temperature 0.1
Pre-LLM prefilter
If the character bigram intersection between the draft and the document is zero, the model is never called at all (relevance estimated without Korean morpheme analysis). The reason the threshold is 1 is left in a comment — raise it, and a draft sharing only "Sokcho" slipped through unchecked
Output post-processing
  • Evidence cross-check verifies the sentence the model quoted actually exists in the document. If not, the decline is voided (guard.ts:168)
  • If either condition is false → allow
  • LLM outage → unconditionally allow. "A guard outage must never block a send."
④ Call fact sheet (once per call) call-watch.ts:70 · factSheet()
Role
At call start, compresses the relationship record into a lookup sheet. Every utterance after that is checked against this sheet instead of the document — the per-utterance cost of reading the document drops to zero
System prompt
"Compress into places / tastes / foods / events / people lines. Only what the record says, in its own wording plus obvious synonyms. A line the record is silent on is (nothing recorded) — that absence itself is meaningful. No prose, no headings"
Context
All non-empty sections, with an 8,000-character cap
Source
OKF file (okfDocTreeFromState — read-only, does not create the document if missing)
Parameters
maxTokens 300 · temperature 0 · cached in process memory per callId
On failure
Proceeds with every line as (nothing recorded) — the call continues
⑤ What is this utterance about call-watch.ts:216 · readLine()
Role
One utterance line → {topic, known}. The model does not decide whether to whisper
System prompt
Loads the whole fact sheet, then: "state what this utterance is about, and whether this relationship has it on record. Resolve pronouns (that place, back then, it). (nothing recorded) means there is nothing of that kind at all. If it isn't really about anything in particular — small talk, a reaction, weather, mood — return {topic:null, known:false}"
Context
The fact sheet built by ④ + just the single line of utterance text (no conversation history)
Parameters
maxTokens 60 · temperature 0
Decided by code
worth = asks || (topic && known) asks is a regex — contains ?, or starts with do/did/what/where/how… (call-watch.ts:39). A question directed at my member is always worth whispering (whether the answer is on record, or the fact that it isn't stands out), while a plain statement is only worth it when it touches the record. Asking the model this once produced a split verdict between "do you like egg tarts?" and "what's your favorite dessert?" — noted in a comment
Delivery
Sent as a privateToUserId message to the member other than the speaker. Shows up in the chat panel beside the call, invisible to the other party
⑥ Call summary (meeting notes) call-watch.ts:175 · writeCallRecap()
Role
One finished call = one Timeline entry. "A meeting leaves minutes, not a transcript." On top of that, whatever the call produced (decisions, open items, notes about people) goes into its own section
System prompt
summary: "Write what this call was about for the two people's shared record. 2–3 sentences, past tense, name what was done, decided, or intended. Only what was actually said — no advice, no invention. Plain text, no headings or bullets"
entries: "Only items that have their own section, as {section, markdown}. Plans the two of them agreed on are a decision, a question left open is an open item, something learned about a person is a people note. The call already goes to the timeline as a summary — never put it there again. If none apply, an empty list"
Context
A display name: utterance transcript, with an 8,000-character cap. Document content is not included
Source
Postgres call_utterances — the unprocessed rows for this callId (names joined from users.displayName)
Parameters
maxTokens 400 · temperature 0.2 · parseRecap never throws (if not JSON, the whole body becomes the summary)
Where it writes
One 📞 callout in Timeline.md; entries get one bullet line each in their own section file. All of them carry Sources: /dm/{roomId}#call-{callId} — since there's no message anchor, the call itself is cited as the source, and that anchor is also the join key linking bubble → record (GET /api/calls/{roomId}/record). What comes back is only the lines left in the document, never the raw utterances
Ordering contract
Claim first — while the call is still alive, utterances are snatched off the queue (one UPDATE). Otherwise the "📞 call ended" message wakes the pipeline, and since the pipeline now has no live call to skip, it scatters the same utterances one line at a time

Permissions — the OKF tree has no filesystem permissions. okf_acl registers a document root path as participants-only, and okfGateFor(userId) enforces that path and everything under it at /p/[pageId]·api/pages·api/okf/*·api/search·api/mcp. Registration happens on both the pipeline path and the call-summary path. Each route has to ask the gate for itself — since a page id is the base64url of the path, an address can be constructed just by knowing the room name, and three routes that forgot to ask (pages/[id], pages/[id]/blocks, okf/db) ended up reading and deleting the document. The regression is now guarded by e2e/okf-acl.check.mjs.
Checkpoint — processedAt is the marker for "the agent has read this." It only advances the transaction after the file write finishes. Since a file can't participate in a DB transaction, if the file write succeeds but the DB write fails, the next run reapplies the same batch — a known tradeoff of the file-as-source-of-truth model.

06 Summary: what the model does / what the code does

PointBlank the model fillsWhat code already decides
① Document editWhich section gets which sentenceWhen it runs, what it's fed, where to append, date event if there's a photo
② ReplyWhether to reply + the wordingMention detection, secret = mention, visibility scope, photo-pick fallback
③ Contradiction checkDoes it contradict / is it harmfulWhether to call at all (bigram), the AND condition, verifying evidence is real, pass-through on outage
④ Fact sheetCompression of the recordWhen it's built, cache lifetime, character cap
⑤ Utterance judgmentWhat the line is aboutWhether to whisper, to whom, wording format
⑥ Call summary2–3 sentence summaryWhen to claim, skip under 2 lines, where it's written, source anchor

At all six points, the decision to act is code's, and the model only fills in content. Anything computable is kept off the model, because the same input would otherwise get a different answer each time — and that decision is left in a code comment along with its reasoning. The one place an autonomous tool loop would actually pay off is ① document editing — right now it can only append, so it structurally cannot revise an existing line, merge a duplicate, or resolve a contradiction.
