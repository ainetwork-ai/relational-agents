관계 에이전트 런타임 지도

무엇이 파이프라인을 깨우고, 파이프라인이 무엇을 하고, LLM이 정확히 어느 지점에서 어떤 프롬프트와 어떤 컨텍스트로 불리는지. 컨텍스트의 출처까지 따라갑니다. 코드베이스 기준: app/src/lib/agent/*, 2026-07-26. 섹션 구성·어휘·이벤트 규칙은 이제 관계 프로필이 정합니다 (lib/agent/profiles) — 아래 값들은 기본값인 Romantic 프로필 기준이고, Business 프로필에서는 섹션이 6개(Meeting log·Agreements·Action items·Contacts· Open questions)이며 사진 규칙이 없고 이벤트가 📅 meeting / 🤝 intro 입니다.

03 LLM 호출 지점 3곳

에이전트가 모델을 부르는 곳은 정확히 세 군데입니다. 각각 프롬프트가 하드코딩돼 있고, 도구는 붙어 있지 않습니다 — 모델은 JSON 텍스트를 반환하고, 그걸 해석해 파일을 쓰는 건 전부 코드입니다.

권한 — OKF 트리에는 파일시스템 권한이 없습니다. okf_acl이 문서 루트 경로를 참여자 전용으로 등록하고, 그 경로와 하위 전체를 okfGateFor(userId)가 /p/[pageId]·api/pages·api/okf/*·api/search·api/mcp에서 막습니다. 등록은 파이프라인에서 합니다. 게이트는 라우트마다 각자 물어야 합니다 — 페이지 id 가 경로의 base64url 이라 방 이름만 알면 주소가 만들어지고, 묻지 않던 세 라우트(pages/[id], pages/[id]/blocks, okf/db)로 문서가 읽히고 지워졌습니다. 회귀는 e2e/okf-acl.check.mjs 가 지킵니다.
체크포인트 — processedAt이 "에이전트가 읽었다"의 표시입니다. 파일 쓰기가 끝난 뒤에야 트랜잭션으로 전진합니다. 파일은 DB 트랜잭션에 참여할 수 없어서, 파일 성공 후 DB 실패 시 다음 런이 같은 배치를 재적용합니다 — 파일 정본 모델의 알려진 트레이드오프입니다.

06 요약: 모델이 하는 일 / 코드가 하는 일

지점모델이 채우는 빈칸코드가 이미 정해둔 것
① 문서 편집어느 섹션에 무슨 문장을언제 돌지, 무엇을 먹일지, 어디에 append할지, 사진이면 date 이벤트
② 답장답할지 + 문안멘션 판정, 비밀=멘션, 공개 범위, 사진 선택 폴백
③ 모순 검사모순인가 / 해로운가호출 여부(바이그램), AND 조건, 증거 실재 확인, 장애 시 통과

세 곳 모두 행동 결정은 코드이고 모델은 내용만 채웁니다. 계산 가능한 판단을 모델에 넘기면 같은 입력에 다른 답이 나오기 때문이고, 그 결정이 코드 주석에 근거와 함께 남아 있습니다. 자율 툴 루프가 값을 하는 곳은 ① 문서 편집 하나입니다 — 지금은 append만 가능해서 기존 줄 수정·중복 병합·모순 정리를 구조적으로 못 합니다.
